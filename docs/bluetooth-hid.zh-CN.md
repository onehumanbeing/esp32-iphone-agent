# 蓝牙键鼠能力与板型适配

[English](bluetooth-hid.md)

蓝牙键鼠让开发板接收 App 指令后，通过 BLE HID 将鼠标、键盘和消费控制报告送回同一台 iPhone。原有标准构建也通过蓝牙接收指令，但键鼠输入走 USB。这两条链路需要分开判断：指令通道连通，不代表手机已经接收键鼠报告。

## 两部分分别负责什么

| 部分 | 职责 |
| --- | --- |
| 通用 BLE HID | 配对和授权、键鼠报告、输入目标与连接会话校验。断线后排队指令失效，新会话不会继承按下的键或按钮。由 `HID_TRANSPORT_BLE` 选择，不依赖 Note 4 板型名称。 |
| App 能力支持 | 根据 `hid` 字段判断蓝牙输入是否就绪，提供通用配对指引，并在输入断开时暂停、恢复和重新校准。`board` 仅表示板型。 |
| Note 4 适配 | 电源保持、外设引脚、电池 ADC 与电量曲线，以及 16 MB Flash 分区配置。详见 [Note 4 板型说明](note4-bluetooth.zh-CN.md)。 |
| 固件更新兼容性 | 区分构建产物和目标镜像，防止蓝牙构建进入现有 USB 发布通道。这是镜像兼容性限制，不代表 BLE HID 设备不能实现 OTA。 |

取图仍使用项目原有 AirPlay/Wi-Fi 路径；启用蓝牙键鼠不会自行提供截图，也没有增加墨水屏或语音功能。

## 构建入口

在仓库根目录执行。蓝牙构建只编译，不会自动刷写。

| 构建 | 命令 | 输出目录 |
| --- | --- | --- |
| 标准 8 MB USB | `hardware/flash.sh --build-only` | `hardware/build/` |
| 标准 8 MB 蓝牙 HID | `hardware/flash.sh --ble-hid --build-only` | `hardware/build/ble-hid/` |
| Note 4 蓝牙 HID | `hardware/flash.sh --note4 --build-only` | `hardware/build/note4/` |

标准蓝牙构建沿用标准 ESP32-S3 的 8 MB Flash、OPI PSRAM 配置，只用于验证蓝牙能力不依赖 Note 4。它不是所有 ESP32 板型的通用刷机包。部署前仍需匹配芯片、Flash、PSRAM 和分区，保存完整 Flash 备份，并按目标板的有线流程刷写。现有网页刷机和 App 固件更新入口只发行标准 USB 镜像。

## 配对与验证

1. 给已装对应蓝牙固件的开发板上电，在三分钟配对窗口内从 App 选择开发板并确认系统配对请求。板名默认以 `ESP32 Agent` 开头。如果构建时使用了 `--name`，请选择以自定义名称开头的设备。设备列表中带有 `CLI` 前缀的是电脑命令行连接入口，请为 iPhone 选择不带此前缀的名称。
2. 在 iPhone 的“设置 → 辅助功能 → 触控 → 辅助触控”开启辅助触控。在“设备”中找到同一块板，将鼠标按钮 2 映射为“主屏幕”。
3. 在 App 诊断页检查指令连接和蓝牙输入状态。`hid: ok` 表示输入链路就绪，不能只凭指令连接成功就开始任务。
4. 完成指针校准，检查手机实际移动、点击和键入。从旧实验固件升级后若保留了旧配对，先在系统设置中忽略旧设备，再重新配对。
5. 按[快速开始](../README.zh-CN.md#快速开始)设置网络和 AirPlay，验证实际任务需要的画面链路。

单元测试、协议模拟和编译只能证明相应代码路径。首次配对、双中心连接竞争、重连和手机实际输入仍须分别在目标硬件上验收。
